## 1. v0.4.1 Candidate: Cancel scan [implemented, accepted]

### Purpose
- D: HDD scan のような長時間 scan を途中で止められるようにする。
- 誤って長い scan を開始した場合の逃げ道を作り、daily usability を改善する。
- WizTree にある cancel 操作との差を縮める。

### Implementation Details

#### Rust/Tauri cooperative cancel
- **src/mft_probe.rs**
  - `build_mft_tree_model_with_policy_progress` に `cancel: &AtomicBool` を追加。
  - CLI / non-cancel callers 用に `no_cancel` を用意し後方互換を維持。
  - read_mft extent loop の ReadFile 完了後に cancel checkpoint を追加。
  - parse / tree build / aggregation / UI model build / cache_save 前後に checkpoint を追加。
  - cancel 時は partial result を返さない。
  - cancel 時は cache_save しない。
- **src-tauri/src/main.rs**
  - `AppState` に `cancel_flag: Mutex<Option<Arc<AtomicBool>>>` を追加。
  - scan ごとに per-scan `Arc<AtomicBool>` を生成。
  - `cancel_scan` Tauri command を追加。
  - AppState 更新前に cancel check を行い、cancel 済みなら arena_cache / lazy_children / wof_size_map を更新しない。

#### UI Cancel button / cancelled state
- **ui/src/main.tsx**
  - `cancelScan()` invoke wrapper を追加。
  - `handleCancelScan()` を追加。
  - scan 中は Scan button の位置に `Cancel scan` button を表示。
  - `scanGenerationRef` による stale result guard を追加。
  - cancel 後に遅れて返った result / error が UI を上書きしないようにした。
  - cached result 表示中に cancel した場合は cached data を維持。
  - no-cache 中に cancel した場合は empty state + neutral message。
  - “Scan cancelled” は赤い error box ではなく neutral banner で表示。
- **ui/src/styles.css**
  - neutral cancel message / cancelled banner 用スタイルを追加。

### Validation Results
- cargo build --release: OK
- npm run build: OK
- npm run tauri build: OK
- C: cancel smoke: OK
- D: long scan cancel smoke: OK
- cached result 中の cancel: OK
- no-cache cancel: OK
- cancel 後の即 re-scan: OK
- stale result overwrite は確認上問題なし
- delete / move / cleanup は追加なし

### Known limitations
- Cancel is cooperative.
- Large single-extent ReadFile 中は、extent 完了まで cancel 応答が遅れる可能性がある。
- partial result は表示しない。
- CLI cancel は対象外。CLI は通常 Ctrl+C で対応。
- progress strip 内 Cancel link は未実装。現状は toolbar の Scan button が Cancel scan に切り替わる。

### Decision
- **Accepted** as v0.4.1 first candidate implementation.
- Safe viewer / delete-free 方針を維持。
- v0.4.1 tag 候補として、もう少し dogfooding 後に判断する。

## 3. v0.4.2 Candidate: B-1 Selected subtree search minimal [planned]

**Date**: 2026-05-30

### Background

post-v0.4.1 dogfooding feedback で以下が B: 不便を感じる問題として挙がった。

- 検索できない場合がある。
  例: C:\Users 選択時に "hide" で検索しても、
  C:\Users\iwadj\AppData\Roaming\Hidemaruo が見つからない。

### Root cause

Filter current results は現在表示されている結果の絞り込みのみ。

| 検索経路 | 問題 |
|---------|------|
| Top directories / Top files | global top-N のみ。Hidemaruo は top-N に入らない |
| Direct children | 選択フォルダ直下 1 段のみ |
| TreeView visible rows | filter 対象外 |
| 未展開の深いノード | UI 側に存在しない |

ArenaCache には全ノードの `name` / `parent_frn` / `dir_children` が存在するため、
Rust/Tauri 側に `search_subtree` command を追加すれば実現可能。新規 I/O は不要。

### Purpose

- 選択中フォルダ配下の深い未展開ノードも検索できるようにする。
- full global search ではなく、selected subtree に限定した最小検索とする。
- delete-free / viewer-first 方針を維持する。

### Planned approach

**Step 1: Rust/Tauri**
- `ArenaCache` に `search_subtree(parent_frn, query, max)` helper を追加する (`src/mft_probe.rs`)。
- `search_subtree` Tauri command を追加する (`src-tauri/src/main.rs`)。
- ArenaCache の `nodes` / `dir_children` を使った BFS/DFS でメモリ内探索。
- 新規ディスク I/O なし。
- マッチしたノードだけ `reconstruct_path()` を呼ぶ（コスト制御）。
- 返却型は既存 `JsonTreeNode` に準拠した `Vec<JsonTreeNode>`。

**Step 2: UI**
- `Search in selected folder...` 入力を既存 Filter current results とは別に追加する (`ui/src/main.tsx`)。
- `SearchResultsPanel` コンポーネントを追加する。
- loading / empty / disabled states を用意する。
- Filter current results は変更しない。

### Scope

| 項目 | 方針 |
|------|------|
| Search scope | selected folder subtree のみ |
| Drive root search | 初期実装では無効（root ≈ global search、性能・UX 責任が大きい） |
| Query length | 2 文字以上で有効 |
| Result limit | max 200 |
| Match target | `node.name` の case-insensitive contains |
| 対象ノード | directories + files 両方 |
| path 全文検索 | 後回し |

### UI design

- 入力 placeholder: `Search in selected folder...`
- Live scan が必要（cached result / no arena_cache 時は disabled）。
  - disabled 時: `Search requires a live scan.`
- 結果は flat list（DirectChildrenPanel とは別 SearchResultsPanel）。
- 各行: relative path / size / percentage / Open in Explorer / Copy path。
- Delete / move / cleanup は一切追加しない。

### Non-goals

- Full drive / global search（v0.5 以降）。
- Regex / wildcard search。
- Extension filter。
- Search result sort options。
- TreeView auto-expand to result。
- Cached result search。
- Delete / move / cleanup。

### Risk controls

- `max_results = 200` で打ち切り。
- `min query length = 2`。
- Drive root search は初期無効。
- match by name first; `reconstruct_path()` はマッチ後のみ実行。
- 結果件数上限に達した場合は `Showing top 200 matches.` を表示。

### Acceptance criteria

1. C: live scan 後、C:\Users を選択。
2. `hide` で検索。
3. `C:\Users\iwadj\AppData\Roaming\Hidemaruo` が結果に表示される。
4. relative path が表示される（full path は Copy path で取得可能）。
5. cached result 中は search disabled。
6. `npm run tauri build` が通る。
7. delete / move / cleanup が追加されていない。

### Status

**[planned]** — 仕様確定済み。実装未着手。
