## 1. v0.4.1 Candidate: Cancel scan [implemented, accepted]

### Purpose
- D: HDD scan のような長時間 scan を途中で止められるようにする。
- 誤って長い scan を開始した場合の逃げ道を作り、daily usability を改善する。
- WizTree にある cancel 操作との差を縮める。

### Implementation Details

#### Rust/Tauri cooperative cancel
- **src/mft_probe.rs**
  - `build_mft_tree_model_with_policy_progress` に `cancel: &AtomicBool` を追加。
  - CLI / non-cancel callers 用に `no_cancel` を用意し後方互換を維持。
  - read_mft extent loop の ReadFile 完了後に cancel checkpoint を追加。
  - parse / tree build / aggregation / UI model build / cache_save 前後に checkpoint を追加。
  - cancel 時は partial result を返さない。
  - cancel 時は cache_save しない。
- **src-tauri/src/main.rs**
  - `AppState` に `cancel_flag: Mutex<Option<Arc<AtomicBool>>>` を追加。
  - scan ごとに per-scan `Arc<AtomicBool>` を生成。
  - `cancel_scan` Tauri command を追加。
  - AppState 更新前に cancel check を行い、cancel 済みなら arena_cache / lazy_children / wof_size_map を更新しない。

#### UI Cancel button / cancelled state
- **ui/src/main.tsx**
  - `cancelScan()` invoke wrapper を追加。
  - `handleCancelScan()` を追加。
  - scan 中は Scan button の位置に `Cancel scan` button を表示。
  - `scanGenerationRef` による stale result guard を追加。
  - cancel 後に遅れて返った result / error が UI を上書きしないようにした。
  - cached result 表示中に cancel した場合は cached data を維持。
  - no-cache 中に cancel した場合は empty state + neutral message。
  - “Scan cancelled” は赤い error box ではなく neutral banner で表示。
- **ui/src/styles.css**
  - neutral cancel message / cancelled banner 用スタイルを追加。

### Validation Results
- cargo build --release: OK
- npm run build: OK
- npm run tauri build: OK
- C: cancel smoke: OK
- D: long scan cancel smoke: OK
- cached result 中の cancel: OK
- no-cache cancel: OK
- cancel 後の即 re-scan: OK
- stale result overwrite は確認上問題なし
- delete / move / cleanup は追加なし

### Known limitations
- Cancel is cooperative.
- Large single-extent ReadFile 中は、extent 完了まで cancel 応答が遅れる可能性がある。
- partial result は表示しない。
- CLI cancel は対象外。CLI は通常 Ctrl+C で対応。
- progress strip 内 Cancel link は未実装。現状は toolbar の Scan button が Cancel scan に切り替わる。

### Decision
- **Accepted** as v0.4.1 first candidate implementation.
- Safe viewer / delete-free 方針を維持。
- v0.4.1 tag 候補として、もう少し dogfooding 後に判断する。

## 3. v0.4.1 Candidate: Selected subtree search minimal (B-1) [implemented, accepted]

### Purpose
- 選択中フォルダ配下の深い階層にある未展開ノードを検索可能にし、特定のフォルダやファイルへの到達性を改善する。
- C:\Users 選択時に "hide" で深い階層の Hidemaruo フォルダを見つける等のユースケースに対応。

### Implementation Details
- **Rust/Tauri**
  - `ArenaCache::search_subtree` によるメモリ内 BFS 検索を実装。
  - `search_subtree` Tauri command を提供。
  - ディスクI/Oを発生させず、スキャン済みデータから高速に検索。
- **UI (ui/src/main.tsx)**
  - `SubtreeSearchPanel` を追加。選択フォルダ直下に表示。
  - 検索結果はフラットリストで表示し、相対パスを表示。
  - Live scan データがある場合のみ有効。Drive root 選択時は無効化。

### Validation
- C:\Users 以下の深い階層の検索テスト: OK
- 相対パス表示およびフルパスコピーの動作: OK
- スキャン中/キャッシュ表示中の無効化制御: OK

### Decision
- **Accepted**. v0.4.1 の 3 つ目の主要改善項目として確定。
- グローバル検索（全ドライブ検索）は将来課題とする。

### Validation

- 各種アクションが正しく full path に対して実行されることを確認。

### Decision
- **Accepted**.
