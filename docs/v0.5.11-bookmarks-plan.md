## 1. Bookmark の対象（MVP スコープ）

### 推奨

- **フォルダ**と**ファイル**の path bookmark。
- これだけで「よく確認する場所・後で確認したい場所へ戻る」という価値は満たせる。

### 非推奨（MVP では入れない）

- **ドライブ単位の bookmark**: 既に Drive selector があり重複。価値が薄い。
- **検索条件の bookmark**: Subtree search 自体がまだ補助機能。状態の永続化は複雑度が跳ね上がる。
- **Insights 結果の bookmark**: Largest items は scan 依存の動的結果。永続化の意味が薄い。

将来拡張余地として「saved query」は残すが、データモデルに `kind` フィールドを持たせて将来の種別追加に耐える形にしておく（後述）。

## 2. Bookmark データ構造

### 2.1 永続キーの決定

**record_index / FRN は永続キーにしない。** 理由：

- FRN はスキャンごとに不変ではない（NTFS は削除後に MFT エントリ番号を再利用する）。
- arena_cache はセッション内の 1 スキャン分しか保持しない。次回起動時には存在しない。

**主キー = `volume_serial` + 正規化小文字 path。**

- `volume_serial`: `GetVolumeInformationW` の 8 桁 hex（既存 `get_volume_serial_hex`）。ドライブレター変更に耐える。
- 正規化 path: 既存 `normalize_raw_path_for_compare`（`\\?\` 除去・`/`→`\`・末尾 `\` 除去）を小文字化して比較キーにする。
- 表示用には**元の大文字小文字を保った path** を別途保存する。

ドライブレター（`C` など）は**表示用にのみ保存**し、照合キーには使わない（volume_serial が真のキー）。

### 2.2 Bookmark エントリ（保存される 1 件）

```jsonc
{
  "id": "b-1717400000000-3",          // 生成 ID（created_at_ms + counter）。UI key / remove 用
  "kind": "directory",                 // "directory" | "file"（将来 "query" 拡張余地）
  "drive_letter": "C",                 // 表示用のみ。照合には使わない
  "volume_serial": "A1B2C3D4",         // 照合キー（ドライブ同定）
  "path": "C:\\Users\\me\\Projects",   // 表示用（元の大文字小文字）
  "path_key": "c:\\users\\me\\projects", // 照合用（正規化小文字）。保存しておくと load 時に再計算不要
  "display_name": "Projects",          // basename。一覧表示の主ラベル
  "note": null,                        // optional ユーザーメモ（MVP-A では UI 出さず、フィールドだけ確保）
  "created_at_unix_ms": 1717400000000,
  "last_seen_at_unix_ms": 1717480000000, // 最後に scan tree 内で実在確認できた時刻
  "last_known_subtree_size": 524288000,  // 最後に確認できたサイズ（folder=subtree, file=alloc）
  "last_known_exists": true              // 直近の照合で tree 内に存在したか
}
```

**設計判断:**

- `record_index` / FRN は**保存しない**（揮発キーなので無意味、混乱の元）。
- `path_key` を保存するのは load のたびに全件正規化する CPU を避けるため。ただし正規化ロジックを変えた場合に備え、load 後に `path` から再計算して `path_key` を上書きしてもよい（migration 余地）。
- `last_known_allocated_size` と `last_known_size` を別々に持つ案もあるが、MVP は**1 サイズフィールド（`last_known_subtree_size`）に統一**。folder は subtree_size、file は final_allocated_size を入れる。種別は `kind` で判別できる。過剰な列は持たない。
- `note` はフィールドだけ確保し、MVP-A では UI 非表示。C 以降で編集 UI を足す。

### 2.3 保存ファイル全体

```jsonc
{
  "schema_version": 1,
  "app_version": "v0.5.11",            // 参考情報。migration 判断には schema_version を使う
  "updated_at_unix_ms": 1717480000000,
  "bookmarks": [ /* 上記エントリの配列 */ ]
}
```

- **全ドライブを 1 ファイルにまとめる**（各エントリが volume_serial を持つので混在可能）。
  - 理由: ドライブごとファイル分割は「現在未接続のドライブの bookmark をどう一覧表示するか」を複雑にする。1 ファイルなら全 bookmark を常に列挙でき、状態（present/missing/unavailable）だけ切り替えればよい。

## 3. 永続化方式

### 3.1 保存先

```
%LOCALAPPDATA%\disk-insight\bookmarks.json
```

- **`cache\` サブディレクトリの外**に置く。
  - 理由: scan-cache はユーザーが「キャッシュ削除」で消す可能性がある運用物。bookmark はユーザー資産であり、cache クリアで一緒に消えてはならない。
- 既存 `local_cache_dir()` とは別に `local_data_dir()`（= `%LOCALAPPDATA%\disk-insight`）ヘルパを足す。

### 3.2 保存・読込

- **保存**: scan-cache と同じ atomic write パターンを流用。
  - `bookmarks.json.tmp-<ms>` に書き → `rename` で本ファイルに置換。rename 失敗時は既存削除→再 rename（既存ロジック踏襲）。
- **読込タイミング**: アプリ起動時に 1 回 `list_bookmarks` で全件ロード。以降はフロント state に保持。add/remove のたびに**全件を書き戻す**（件数は数十〜数百想定なので全書き換えで十分。差分書き込みは不要）。
- **version field**: `schema_version: 1`。読込時に一致確認。不一致なら将来の migration 関数に分岐（MVP は「未知バージョンは読まずバックアップして空で開始」）。

### 3.3 壊れた JSON への対応

- パース失敗時は **`bookmarks.json.corrupt-<ms>` にリネーム退避**し、空の bookmark セットで起動する（クラッシュさせない）。
- フロントには `{ ok: false, recovered: true }` 的な情報を返し、軽い通知（"Bookmarks file was unreadable and has been reset; a backup was kept."）を出す。

### 3.4 複数ドライブ対応

- 1 ファイルに全 volume_serial 混在。
- 一覧表示時、各 bookmark の volume_serial が「今このセッションで scan/cache 済みのドライブ」と一致するかで present/unavailable を分岐。

## 4. スキャン結果との照合

### 4.1 照合のタイミング

- live scan 完了時、または cached load 完了時に、**そのドライブの volume_serial に一致する bookmark** だけを照合対象にする。
- 照合は遅延でよい（TreeView 表示をブロックしない）。scan 完了後に非同期で実行。

### 4.2 path → ノード解決（新 Rust コマンド）

現状 `ArenaCache` は **path→FRN の下方向解決を持たない**（`reconstruct_path` は上方向のみ）。これを新設する。

```rust
// 与えられた絶対 path を、FRN 5（NTFS root）から name で降りて解決する。
// 戻り値は root 直下 → ... → target までのノード列（jump 用の祖先チェーン）。
// 見つからなければ None。
pub fn resolve_path_chain(&self, path: &str) -> Option<Vec<JsonTreeNode>>
```

実装方針（cheap, O(depth × children/level)）:

1. `path` を正規化（drive root を剥がし、`\` で components 分割）。
2. `cur_frn = 5`（root）から開始。
3. 各 component について `dir_children[cur_frn]` を走査し、`name` を **case-insensitive** で一致する子を探す。
4. 一致した子を chain に push、`cur_frn = child_frn`。
5. 最後の component まで到達できたら chain を返す。途中で見つからなければ None（= missing）。

- 各レベルは線形走査だが、`dir_children` は per-directory なので 1 レベルの子数に比例。深さ × 子数で実用上十分速い。
- これは `is_same_path` と同じ正規化規約に合わせる（小文字 + `\\?\` 除去）。

### 4.3 状態の 3 分類

| 状態 | 条件 | 表示 |
|------|------|------|
| **present** | bookmark の volume_serial がスキャン済みドライブと一致 **かつ** `resolve_path_chain` が Some | 通常表示 + current size |
| **missing** | volume_serial 一致するが `resolve_path_chain` が None | グレー表示 + "not found in last scan" |
| **unavailable** | volume_serial がこのセッションで未スキャン | 淡色表示 + "scan {drive}: to check" |

### 4.4 Recycle Bin へ移動した場合

- ファイルを Recycle Bin に送ると元 path には存在しなくなる → 次回照合で **missing** になる。
- これは正しい挙動として扱う（特別扱い不要）。missing 表示のまま remove をユーザーに委ねる。
- 既存の recycle 機能とは独立。bookmark 側は「実在するかどうか」だけを見る。

### 4.5 case-insensitive / 正規化

- Windows path は大文字小文字を区別しない → **照合は必ず小文字化**。
- 既存 `normalize_raw_path_for_compare` + `.to_lowercase()`（= `is_same_path` と同じ規約）を Rust 側の解決でも使う。
- フロントで path 比較する場面（重複 add 防止など）も同じ規約に揃える（小文字 + 末尾 `\` 除去）。

## 5. UI 配置

### 5.1 大原則

- **Tree-first を壊さない**。bookmark は TreeView の補助であり主役を奪わない。
- **右ペイン inspector には一覧を置かない**（v0.5.9 で苦労して減らした情報量を戻さない）。

### 5.2 配置（推奨）

**(a) TreeView 直上の折りたたみ "Bookmarks" バー**

```
┌─ folder-nav ──────────────────────────────┐
│ ▸ Bookmarks (3)                      [☆]  │  ← 折りたたみヘッダ。デフォルト畳む
│ ──────────────────────────────────────────│  （開くと一覧。各行クリックで jump）
│ Folder tree                                │
│  ▸ C:\                                     │
│    ▸ Program Files                         │
│    ...                                     │
└────────────────────────────────────────────┘
```

- デフォルト**折りたたみ**。ヘッダに件数のみ（`Bookmarks (3)`）。
- 開くと bookmark 一覧（最大数件は inline、多ければ内部スクロール）。
- 一覧の各行: `display_name` + size + 状態バッジ。クリックで jump。行末に remove(×)。
- folder-nav の中（tree の上）に置くことで「ツリー操作の文脈」に self-contained に収まる。

**(b) SelectedFolderCard ヘッダの ★ トグル**

- 右ペインの選択フォルダカードのタイトル横に ★（add）/ ★済み（remove）トグルを 1 つだけ足す。
- これは「情報を増やす」のではなく「1 アクションボタンを足す」だけなので右ペイン複雑化には当たらない。

**(c) context menu の Add/Remove bookmark**（後述 §7）

### 5.3 非推奨

- 常時展開の大きな bookmark パネル（画面を食う）。
- 右ペインに list + size 比較を全部盛る（再クラッタ化）。
- TreeView とは別タブ/別画面（Tree-first の単一画面性を壊す）。

## 6. Bookmark 一覧の機能（MVP）

| 機能 | MVP | 備考 |
|------|-----|------|
| 一覧表示 | ✅ | folder-nav 上部の折りたたみ内 |
| click で jump | ✅ (B) | 該当 path を TreeView で展開・選択 |
| missing グレー表示 | ✅ (B) | クリックしても展開せず軽い通知 |
| unavailable 表示 | ✅ (B) | "scan X: to check" |
| remove | ✅ (A) | 行末 × / context menu |
| current size 表示 | ✅ (B) | present のみ。chain 末尾ノードの subtree_size |
| last known size 表示 | △ (C) | current との差分表示は C |
| note 編集 | ✕ MVP外 | フィールドだけ確保 |
| 並び替え / フォルダ分け | ✕ MVP外 | created_at 昇順固定でよい |

### 6.1 jump の実装（既存ロジック流用可否）

**流用できるもの:**

- lazy 展開の仕組み（`expandedIds: Set<FRN>`, `childrenByParent`, `get_children_limited`）はそのまま使える。
- `buildVisibleRows` も変更不要（expandedIds を増やせば自動的に行が出る）。

**新たに必要なもの:**

- `resolve_path_chain`（§4.2）で root→target の FRN チェーンを取得。
- jump 手順:
  1. `resolve_path_chain(path)` → chain（present 確認も兼ねる）。
  2. chain の各**ディレクトリ**祖先について、`childrenByParent` 未ロードなら `get_children_limited` でロードし、`expandedIds` に追加。
  3. target の record_index を `setFocusedRecordIndex` + `setSelectedDir`。
  4. 既存の scroll-into-view useEffect（focusedRecordIndex 依存）が該当行へスクロール。

### 6.2 巨大フォルダで重くしない

- chain の各レベルは `get_children_limited(300)` を使う（既存の WinSxS 安全制限を踏襲）。
- target が「上位 300 件に入らない子」だった場合、その階層では行として表示されない可能性がある。
  - MVP の割り切り: その場合は「present だが tree 上で可視化はできない」→ jump は親フォルダまで展開し、"This item is beyond the top 300 shown — use Insights › Search inside" の軽い注記を出す。
  - 完全可視化は virtual scroll 導入後（別フェーズ）。

## 7. context menu との統合

### 7.1 追加項目

| 項目 | 表示条件 | 動作 |
|------|----------|------|
| **Add bookmark** | bookmark 未登録の時。**Safe 表示（Advanced 不要）** | 現 path を bookmark に追加 |
| **Remove bookmark** | bookmark 済みの時。Safe 表示 | 該当 bookmark を削除 |
| Show bookmark（任意） | C 以降 | 一覧を開いて該当行へ |

- 既存の `Copy path` / `Copy as path` はそのまま。
- **Add/Remove は Safe section に置く**（破壊的でないため Advanced Mode 限定にしない）。
- `Move to Recycle Bin`（Advanced 限定）とは**セパレータで明確に分離**。bookmark は安全側グループ。

### 7.2 SafeContextMenu への足し方

- 現状の `SafeContextMenu` は `target: ContextMenuTarget` を受け、Safe 項目群（Open/Reveal, Open terminal, Show properties, Copy path, Copy as path）+ Advanced(Recycle) の構成。
- bookmark トグルは Safe 項目群の末尾（Copy as path の後、Advanced separator の前）に 1 項目。
- 登録済みかの判定はフロント state（bookmark 配列）を `is_same_path` 規約で検索して boolean を渡す。

## 10. テスト観点

| 区分 | 観点 |
|------|------|
| 永続化 | 追加→再起動→残存 / remove→再起動→消えている / 全ドライブ混在 |
| 原子性 | 保存中クラッシュでも本ファイルが壊れない（tmp 経由） |
| 壊れ JSON | 不正 JSON → .corrupt 退避 → 空起動・通知 |
| 正規化 | `C:\X` と `c:\x\` が同一 bookmark 扱い / `\\?\` 付き path |
| Unicode | 日本語フォルダ名・絵文字を含む path の保存・照合・表示 |
| volume_serial | ドライブレター変更後も同ボリュームの bookmark が present |
| 照合(B) | present / missing / unavailable の 3 状態が正しく出る |
| jump(B) | 浅い path・深い path・top300 外の子・root 直下 |
| missing(B) | recycle 後 missing / 削除後 missing でクラッシュしない |
| 性能 | bookmark 数百件で起動・一覧・jump が体感遅延なし / TreeView 操作が v0.5.10-B から悪化しない |
| context menu | Add/Remove が Safe 表示 / Recycle と分離 / Advanced 不要 |

## 11. Known risks

| リスク | 内容 | 緩和策 |
|--------|------|--------|
| path normalization 不一致 | フロントと Rust で正規化規約がずれると重複 add / 照合漏れ | `is_same_path` と同一規約（小文字+`\\?\`除去+末尾`\`除去）に両側を揃える |
| drive letter 変更 | C: が D: に変わると path 主キーがずれる | 照合キーは volume_serial。path はその volume 内での相対同定 |
| stale bookmarks | 古い path が大量に missing 化 | missing でも破綻させない / ユーザーが remove できる / C で last_seen 表示 |
| deleted/recycled | 実体消失で missing | 正常挙動として扱う。特別処理なし |
| scan cache との関係 | cache クリアで bookmark が消えると事故 | bookmarks.json は cache/ の外に置く |
| top 300 制限 | 深い/大量フォルダで target が tree に出ない | 親まで展開 + 注記。完全可視化は virtual scroll 後 |
| UI 複雑度の逆戻り | 右ペイン再クラッタ | 一覧は folder-nav 上部のみ。右ペインは ★ 1 個だけ |
| 性能影響 | 起動時ロード・照合が重い | 数百件想定で全件ロードで十分。照合は scan 後非同期 |
| FRN を永続化する誘惑 | うっかり record_index を保存して次回ズレる | スキーマに FRN を入れない（設計で明示排除） |

## 12. dogfooding 判定基準

v0.5.11 完了時、以下が満たせれば成功:

1. 気になる folder/file を **context menu または ★ から bookmark** でき、再起動後も残る。
2. 次回スキャン後、**Bookmarks 一覧から click でその場所に戻れる**（tree が展開・選択される）。
3. 実体が消えた bookmark も **missing 表示で破綻せず**、remove できる。
4. 未スキャンドライブの bookmark は **unavailable** と分かる。
5. **Tree-first 画面が複雑に戻っていない**（右ペインは ★ 1 個追加のみ、一覧は折りたたみ既定）。
6. 「よく見る場所にすぐ戻れる」点が **WizTree にはない便利さ**として体感できる。
