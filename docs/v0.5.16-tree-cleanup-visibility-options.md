# v0.5.16-D TreeView cleanup visibility — 比較案まとめ

## ステータス

- 静的モック `docs/ui-mocks/tree-cleanup-visibility-options.html` でブラウザ確認可能。
- **本フェーズ (v0.5.16-D) は本実装しない。** docs / mock のみ。
- `ui/src/cleanupSafety.ts`（v0.5.16-B）は残しているが、まだ TreeView に接続していない。
- 実装に進む前にユーザーが第一/第二候補を選ぶ。

---

## 背景

### v0.5.16-C → C2 の経緯

- v0.5.16-C で `SelectedFolderCard`（右ペイン）に cleanup guidance を表示した。
- 実機確認の結果、「選択後に説明を読む UI」になっており目的と合わなかった。
- v0.5.16-C2 で削除。classifier (`cleanupSafety.ts`) は future use として残置。

### 本来の目的（TreeView 完結）

TreeView 上で、以下を素早く見つけたい:

1. どこが多くのディスクを使っているか
2. かつ、削除・確認できそうか
3. 逆に、手動で触ると危なそうな場所はどこか

→ 右/下ペインで説明を読むのではなく、**容量を見ている TreeView の中で安全性も把握**したい。

### 制約（v0.5.16-D で守るもの）

- アプリ本体 UI は変更しない（`main.tsx` / `styles.css` 無変更）。
- classifier はまだ TreeView に接続しない。
- Delete / Cut / Move / multi-select は追加しない。
- 「safe to delete」「delete recommended」などの文言は使わない。
- 行背景全体の強調は避ける。
- TreeView をごちゃつかせない。
- **容量バー（量）と safety marker（安全性）の役割を分ける。**

## Safety tone 凡例（`cleanupSafety.ts` と対応）

| tone | category | 意味（中立表現） |
|------|----------|------------------|
| strong-caution | protected-system | 手動操作は避ける |
| caution | app-managed | アプリ経由（設定／アンインストーラ）を推奨 |
| review | recycle-bin / temp / cache / dev-dependency | 確認候補 |
| neutral | user-data | 内容を理解している時のみ |
| none | unknown | 指針なし（表示控えめ） |

> 分類はパス文字列のヒューリスティック。disk-insight は削除を推奨しない。

## 比較表（評価軸別）

| Option | Finds large cleanup targets quickly | Keeps TreeView simple | Avoids delete recommendation | Works with occupancy bars | Risk |
|--------|:---:|:---:|:---:|:---:|------|
| A 現状維持 | △ | ◎ | ◎ | ◎ | 低（安全性が分からない） |
| B marker 列 | ○ | △ | ○ | ◎ | 中（記号のノイズ・直感性） |
| C name pill | ○ | △ | ○ | ◎ | 中（name 列圧迫） |
| D bar accent | ○ | ○ | △ | ✗ | **高（容量と安全性の二重エンコード）** |
| E filter/view | ◎ | ◎ | ○ | ◎ | 中（気づきにくさ・lazy 展開整合） |
| F Insights list | ○ | ◎ | ○ | ◎ | 中（TreeView 完結から離れる） |

評価軸:

- **Finds large cleanup targets quickly** — 大きくて確認対象になりそうな場所を素早く見つけられるか
- **Keeps TreeView simple** — TreeView がごちゃつかないか
- **Avoids delete recommendation** — 削除推奨に見えないか
- **Works with occupancy bars** — occupancy bar（容量）と競合しないか
- **Risk** — 実装リスク / 誤誘導リスク

## 案別詳細

### 案 A: 現状維持（ベースライン）

shipped TreeView そのまま。占有率バー + % + size。cleanup 補助なし。

- 長所: 最もシンプル、容量把握に集中、削除推奨に一切見えない。
- 短所: 「触ってよいか／危ないか」が分からない。目的 (2)(3) を満たさない。

### 案 B: safety marker 列〈第二候補〉

name の前に細い marker 列を追加。`!!`=protected-system / `!`=app-managed / `?`=review candidate / 空欄=user-data・unknown。

- 長所: 容量バーと別列なので役割が混ざらない。TreeView 完結に近い。
- 短所: 記号がノイズになりうる。`!!` / `?` の意味が直感的か不明（凡例 or tooltip 必須）。
- 検討: 記号より**色ドット**の方が直感的な可能性。要ユーザー確認。

### 案 C: name 直後に category pill

name の後に `system` / `app` / `review` pill。user-data / unknown には出さない。

- 長所: 文字で意味が明確。
- 短所: **name 列を圧迫**。長い名前（System Volume Information 等）で省略記号と干渉。pill が増えるとうるさい。

### 案 D: 占有率バーに tone accent

占有率バーの fill 色と左端に tone を載せる。

- 長所: 列を増やさず一体化。
- 短所: **バーの意味が「容量」か「安全性」かで混ざる（二重エンコード）。** 赤バー=危険と誤読されうる。比較中で誤誘導リスク最大。

### 案 E: filter / view mode〈第一候補〉

TreeView header に view 切替（`All` / `Large review candidates` / `Caution areas`）。通常は All（＝案 A）で無変更。切替時のみ確認候補に絞る。

- 長所: 常時表示のシンプルさを完全維持。「素早く見つける」に直結。「確認候補」フレーミングで削除推奨を避けられる。
- 短所: view 切替に気づきにくい可能性。絞り込み時の lazy 展開の扱い（全展開して分類 vs 既知ノードのみ）を設計で詰める必要。

### 案 F: Insights に candidates リスト

TreeView 無変更。Insights パネルに “Large review candidates” 一覧。

- 長所: TreeView を汚さない。候補が一覧化される。
- 短所: TreeView 完結から離れ、右/下ペイン依存に戻る（dogfooding で「右/下ペインは要らない」FB あり）。E の補助としてなら有効。

---

## 推奨

### 第一候補: 案 E（filter / view mode）

- “Large review candidates” に絞り込めて目的に直結。
- 通常は All で現状のシンプルさを維持。
- 「削除してよい」ではなく「確認候補」にできる。
- 要設計: view 切替の発見性、lazy 展開との整合。

### 第二候補: 案 B（safety marker 列）

- TreeView 完結に近く、容量バーと役割を分離。
- 要検討: マーカー記号のノイズと直感性（色ドット案との比較）。

### 見送り寄り

- **案 D**: 容量バーの意味が混ざり誤誘導リスク最大。
- **案 C**: name 列圧迫が大きい。
- **案 F**: 目的には合うが TreeView 完結から離れる。優先度低（E の補助なら可）。

---

## ユーザーへの確認事項

実装に進む前に確認する:

1. **第一候補 E / 第二候補 B のどちらを実装するか**（併用も可）。
2. **B を選ぶ場合、記号 (!! / ! / ?) か色ドットか。**
3. **E を選ぶ場合、view の種類**（`All` / `Large review candidates` / `Caution areas` で十分か）。
4. **絞り込み時の lazy 展開の扱い**（既知ノードのみ vs 必要範囲を展開して分類）。
5. **review candidate の閾値**（全件か、`≥N%` / `≥N GB` の大きいものだけか）。
