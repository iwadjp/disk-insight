# v0.5.15 TreeView 容量可視化 — 比較案まとめ

## ステータス

v0.5.15-A/B の実装（行背景色強調）は revert 済み。  
静的モック `docs/ui-mocks/tree-capacity-visual-options.html` でブラウザ確認可能。  
**実装前にユーザー確認を挟む。**

---

## 背景

### dogfooding フィードバック

- 「ドライブの中でディスクを消費しているフォルダが分かりにくい」
- 「% だけだと、どの程度なのかが直感的に伝わってこない」
- 「今のシンプルな画面が悪いとは感じない」
- 「一定以上のノードを強調する案はあるが、好みも含めて難しい」
- **「WizTree は TreeView の占有率がバー表示されていて分かりやすい」**
- 「右/下ペインの情報が必要とは思わない」

### v0.5.15-A/B が合わなかった理由

| 問題 | 詳細 |
|------|------|
| 行背景色が違和感 | 選択行 (blue) / hover / focus と競合しやすく視覚的にうるさい |
| 画面全体が一貫しない | TreeView だけ変わり、Largest / Top リストが変わらない |
| 適用範囲が未整理 | "TreeView だけ" という前提が適切かどうかを事前確認していなかった |

---

## WizTree スクリーンショットから得た示唆

- TreeView の各行に「占有率」バーが並んでいる
- バーの長さで相対的な大きさが即座に分かる
- 右/下ペインは使わない — **TreeView 内で容量感が完結している**
- 行背景の色変化ではなく、列追加（バー）による視覚化
- 数字と視覚的なバーの両方が同じ行にある

## 比較案サマリー

| 案 | 表現 | 閾値 | 実装コスト | 推奨度 |
|----|------|------|-----------|--------|
| A | 現状のまま | — | 0 | ベースライン |
| B | 占有率バー列を追加 | 全行（閾値なし） | 中 | **最有力** |
| C | size/% 数字を強調 | ≥N% | 低 | サブ候補 |
| D | size bar を明確化（%比例） | 全行（閾値なし） | 低〜中 | 候補 |
| E | badge 表示 | ≥N% | 低 | 参考のみ |

## 案別詳細

### 案 A: 現状（ベースライン）

現在の disk-insight TreeView。薄い blue size bar + size/% 数字。  
比較の基準として使う。

**評価**:
- 大きいフォルダが一目で分かるか: △（数字を読む必要あり）
- シンプルさ: ◎（変更なし）
- 競合なし: ◎

---

### 案 B: 占有率バー列（WizTree 風）〈最有力〉

「占有率 (Occ.)」列を追加し、セル内にミニ横バー + % を表示する。  
WizTree が採用しており、「分かりやすい」と FB で言及された方式。

```
[▶][📁] Users            90.2 GB  [███████████    ] 47.6%
[▶][📁] Program Files    29.9 GB  [████           ] 15.8%
[▶][📁] Windows          27.0 GB  [███            ] 14.2%
```

**メリット**:
- バーの長さで容量感が即座に伝わる
- 行背景を変えないため選択/hover と競合しない
- WizTree ユーザーに馴染みやすい

**デメリット**:
- 占有率列分だけ横幅を使う → name 列が短くなる可能性
- 列を追加するため、Largest/Top テーブルとは別に実装が必要

**実装の注意点**:
- 固定幅 (120px 程度) または非表示切り替えを検討
- expanded フォルダ内の子行では denominator が何か要確認（ドライブ全体 vs. 親フォルダ）

---

### 案 C: size/% 数字だけ強調

閾値（例: ≥5%）以上のノードの size/% 数字を太字 + warm brown color に変える。  
行背景・列数は変えない。

```
[▶][📁] Users            **90.2 GB · 47.6%**  ← 太字・暖色
[▶][📁] Windows            27.0 GB · 14.2%    ← 通常
```

**メリット**:
- 実装コストが最低
- レイアウトを一切変えない
- Largest/Top リストにも同じ CSS class で共通化しやすい

**デメリット**:
- 「量感」（どれだけ大きいか）は伝わりにくい
- 数字を見て初めて分かる

---

### 案 D: size bar を明確化

現在の薄い blue size bar（opacity 9%）をより見えるようにする。  
全行でバーを常時表示し、% 比例の長さ + やや濃い opacity。

**メリット**:
- 列数を変えずに視覚的な容量感を追加
- 相対感が出る

**デメリット**:
- active row の blue 背景と size bar の blue が重なる可能性
- opacity を動的計算するとパフォーマンスへの影響を確認要（TreeNodeRow memo）

**実装の注意点**:
- opacity を固定（例: 25%）にする単純実装も検討可
- 動的な opacity = pct * 0.004 + 0.05 等で %に比例させる案もある

---

### 案 E: badge（参考）

閾値以上に「large」バッジを付ける。

```
[▶][📁] Users   [large] 90.2 GB · 47.6%
```

4件以上にバッジが付くと視覚的にうるさくなるため、参考案扱い。

## 評価マトリクス

| 評価軸 | A | B | C | D | E |
|--------|---|---|---|---|---|
| 大きいフォルダが一目で分かるか | △ | ◎ | ○ | ○ | ○ |
| シンプルさを維持しているか | ◎ | ○ | ◎ | ○ | △ |
| TreeView 内で容量把握できるか | △ | ◎ | ○ | ○ | △ |
| 選択/hover/focus と競合しないか | ◎ | ◎ | ◎ | △ | ◎ |

## 実装候補の推奨順位

1. **案 B（占有率バー列）**: WizTree 類似で「分かりやすい」FB 根拠あり。
   ただし横幅トレードオフをユーザーが許容できるか確認要。

2. **案 C（size/% 強調）**: シンプルさ重視なら。案 B と組み合わせる (B + C) も可。

3. **案 D（bar 強化）**: 列追加なしで視覚改善したいなら。
   active row との競合を調整できるなら実装コスト低。

4. **案 E（badge）**: 補助的用途のみ。主案には不向き。

## ユーザーへの確認事項

実装前に以下を確認する:

1. **どの案が最も「一目で分かる」か** — 案 B / C / D から選ぶ
2. **シンプルさを壊していないのはどれか** — 案 A との違いをどこまで許容するか
3. **TreeView だけか、Largest/Top/Search にも入れるか**
4. **閾値強調が必要か、全行バー表示でよいか**
5. **% のみか、絶対サイズ条件（≥10GB など）も必要か**
