## 0. 結論（先に出す）

**採用 = 案A（WizTree-like simple mode）。決定的に。**

> disk-insight の TreeView は**既に WizTree 相当**である（name + allocated size + % +
> インライン size bar + size 降順 + lazy 展開 + 右クリック + recycled badge）。
> 「ツリーが弱い」のではなく、**右ペインに 4 パネルが縦積みされ、その大半がツリーと冗長**なことが
> 「複雑で見づらい」の正体。
>
> 解決は「ツリーを作り直す」ことではなく、**冗長な右ペインパネルを既定から外し（progressive
> disclosure）、ツリーを明確に主役に据える**こと。

| 案 | 判定 | 理由 |
|----|------|------|
| **案A: WizTree-like simple mode** | **採用（主軸）** | ユーザーは WizTree 代替を求め、複雑さが dogfooding の阻害要因。ツリーは既に十分。 |
| **案B: dashboard mode** | **却下** | 「複数パネルの価値が実感できない」と複数セッションで明言済み。既存の複雑さを正当化する方向。 |

**重要な原則: 案A は「機能削除」ではなく「既定でシンプル、詳細はオンデマンド」。**
唯一ツリーにない付加価値（Largest items の深い子孫ランキング）と独自価値（Reclaimable）は
残すが、常時表示ではなく折りたたみ／オンデマンドにする。

**第2の global UI mode（Simple/Advanced UI トグル）は導入しない。**
既に "Advanced Mode"（Recycle 用）があり、2 つ目の "Advanced" は混乱を生む。
モードではなく既定折りたたみ（progressive disclosure）で簡素化する。

## 1. WizTree の TreeView 完結型ワークフロー分解

### なぜ TreeView だけで使いやすいのか
- **単一グリッドで完結**: 1 つのツリー（=表）の中で「サイズ降順 → 大きいものを展開 →
  さらに大きい子を展開」と降りていける。視線が 1 箇所から動かない。
- **サイズが常に見える**: 各行に Size / Allocated / % / バーが並び、どこが容量を食うか一目。
- **操作もその場**: 右クリックで Explorer 相当の操作がツリー行から直接できる。
- **追加パネルを見に行く必要がない**: 「このフォルダの中身」=その行を開くこと、と同義。

### disk-insight の現状との差分
- disk-insight の**ツリー自体は WizTree 相当**（§0 参照）。コア機能は揃っている。
- 差は「ツリーの外」にある。右ペインに 4 パネルが縦積みされ、ツリーと**役割が重複**している：
  - **Selected folder contents（DirectChildren）= 選択フォルダをツリーで展開したのと同じ内容。**
    純粋な重複。最大の冗長源。
  - **Top scan results = v0.5.5 の Largest items に機能上書きされた最弱コンポーネント。**
  - Largest items = 唯一ツリーにない価値（深い子孫の横断ランキング）。
  - Search inside = 名前検索。たまに使う補助。
  - Reclaimable = disk-insight 独自価値（既に折りたたみ済み・非侵襲）。

### 何が「画面が複雑」に感じさせるか
- 起動・フォルダ選択時、右ペインが **SelectedFolderCard → filter → DirectChildren+Search →
  Largest items（フォルダ表+ファイル表）→ Top scan results** と**長く縦に積まれる**。
- そのうち 3 つ（DirectChildren / Top scan results / 一部 Search）は**ツリーで足りる情報の再掲**。
- 「ツリーを見ればいいのか、右ペインを見ればいいのか」が**毎回判断を迫られる** → 疲れる。

## 2. 現コンポーネント棚卸し（扱い表）

| コンポーネント | 現状 | v0.5.9 での扱い | 理由 |
|----------------|------|-----------------|------|
| **Folder tree** | 常時・左 420px | **主役（hero）。さらに広く・主画面化** | 既に WizTree 相当。これが製品本体。 |
| **SelectedFolderCard** | 常時・右上 | **残す。選択行の "inspector" として右ペインの存在理由に** | path + サイズ + アクション。簡素な詳細ペイン。 |
| **Reclaimable estimate** | カード内 details（折畳） | **inspector 内に折畳のまま残す** | 独自価値・非侵襲。現状で良い。 |
| **Selected folder contents（DirectChildren）** | 常時・右 | **既定表示から外す（Insights へ退避、削除はしない）** | ツリー展開の純粋な重複。最大の冗長源。 |
| **Largest items in selected folder** | 常時・右（表×2） | **既定折りたたみ（Insights の主役）** | 唯一ツリーにない価値。オンデマンドで残す。 |
| **Search inside selected folder** | details（折畳） | **オンデマンド（ツリーヘッダの検索 or Insights）** | たまに使う補助。 |
| **Top scan results** | details（折畳） | **既定表示から外す（Insights 最下部 or debug 扱い）** | 最弱。Largest items に上書き済み。 |
| **Context menu** | 共有 | **残す。ツリー行の主操作面として強化** | 既に Show in Explorer / terminal / properties / copy / recycle。 |
| **Banners** | 上部 | **残す。既に最小限** | error / handoff / recycle / cache。現状で良い。 |
| **filter input（Filter visible result lists）** | 右ペイン上 | **再検討: 退避パネルに付随移動 or ツリー filter に統合** | 退避するパネル前提の filter なので役割が薄くなる。 |

### 「ツリーだけでは不足する価値」があるのはどれか
- **Largest items in selected folder のみ。** ツリーは各階層の直下しか見せないが、これは
  選択サブツリー全体の深い子孫を横断ランキングする（WizTree にもない、disk-insight の差別化候補）。
  → だから消さない。ただし**常時表示ではなくオンデマンド**にする。
- Reclaimable も独自だが既に折畳で非侵襲。
- それ以外（DirectChildren / Top scan results）は**ツリーで代替可能**。

## 3. 案A / 案B 比較

### 案A: WizTree-like simple mode（採用）
- TreeView を主画面化（より広く）。右ペインは**選択項目の小さな inspector + アクション**に限定。
- DirectChildren / Largest items / Search / Top scan results は**既定折りたたみ or Insights へ退避**。
- 起動直後 = 「大きなツリー + 小さな inspector」。WizTree の感覚。
- **長所**: 複雑さが即座に消える。ツリー完結の操作導線。dogfooding の阻害要因を直接除去。
- **短所**: Largest items の付加価値が既定では見えない → Insights 導線の発見性に依存。

### 案B: disk-insight dashboard mode（却下）
- 複数パネルを残し、役割と視線誘導を再設計。
- **長所**: 全機能が常時見える。
- **短所**: ユーザーが「複数パネルの価値を実感できない/複雑」と**複数セッションで明言済み**。
  視線誘導の再設計を頑張っても「パネルが多い」根本は変わらない。既存の複雑さを正当化する方向。

### なぜ A か
ユーザーの一貫した要望は「WizTree 代替」「複雑さが阻害要因」。
ツリーは既に WizTree 相当なので、**足し算（B）ではなく引き算（A）が正解**。
付加価値（Largest items）は捨てず、オンデマンドに退避することで「シンプルな既定 + 必要時の深掘り」を両立する。

## 4. v0.5.9-A / B / C 実装分割案

### v0.5.9-A: Tree-first layout（右ペイン簡素化）— 低リスク・最優先
- **対象**: `ui/src/main.tsx` の App return（content-pane / content-right）、`ui/src/styles.css`。
- **やること**:
  1. **右ペイン既定 = SelectedFolderCard（inspector）のみ**にする。Reclaimable は折畳のまま内包。
  2. **Largest items を既定折りたたみ `<details>`** にする（Top scan results と同じ作法）。
  3. **DirectChildren を既定表示から外す**（後述 Insights へ。コンポーネントは残す）。
  4. **Top scan results を Insights 最下部へ退避**（既に折畳なので位置移動のみ）。
  5. **ツリーをさらに広く**（420px → 例: 480–520px or 比率ベース）。inspector はナロー化。
  6. filter input は退避パネルに付随移動 or 一旦隠す（§6 で決定）。
- **リスク**: 低（純フロント、JSX 並べ替え + CSS）。
- **新規 unsafe / Rust 変更**: なし。

### v0.5.9-B: ツリーを主操作面として強化
- **対象**: `ui/src/main.tsx` の TreeNodeRow / TreeView、`ui/src/styles.css`。
- **やること**:
  - サイズ列の桁揃え（現在インライン右寄せ → 擬似カラムで縦に揃える）で一覧性向上。
  - 行ホバー時のアクション可視化（任意）。右クリック導線は既に全部入り（Show in Explorer /
    Open terminal / properties / copy / Advanced で Recycle）。
  - 選択・キーボードナビ・コンテキストメニューが first-class に感じられるよう微調整。
  - → 「TreeView だけで完結」を体感として成立させる。
- **リスク**: 低〜中（行レンダリング調整）。

### v0.5.9-C: オンデマンド Insights
- **対象**: `ui/src/main.tsx`。
- **やること**:
  - 単一の明確な disclosure（例: 「▸ Insights for this folder」）を inspector の下に置き、
    **Largest items（深い子孫ランキング）/ Search / DirectChildren / Top scan results** を
    その中に格納。既定折りたたみ。
  - Reclaimable は inspector に残す（移動しない）。
  - 第2の global mode は作らない。あくまで折りたたみ。

## 7. dogfooding 判定基準

v0.5.9 が「dogfooding したくなる」状態に達したかを、以下の**行動ベース**で判定する：

1. **ツリーだけで完結するか**: スキャン後、最大の容量食いを**ツリーのみ**で見つけ、
   右クリックで操作（Explorer/terminal/recycle）できる。右ペインを縦スクロールしなくてよい。
2. **起動直後の第一印象**: 「ダッシュボード」ではなく「ツリー（表）」に見える。
   情報過多で疲れない。
3. **クリーンアップ 1 周を完走できるか**: 探す → inspector で確認 → recycle/handoff、を
   DirectChildren / Top scan results を**一度も開かずに**完了できる。
4. **深掘りが必要なときだけ Insights を開く**: Largest items / Search を「必要なときに開く」
   感覚で、常時見えていないことが負担にならない。
5. **主観的最終判定**: 「ちょっとディスク容量を見たい」とき、WizTree ではなく
   disk-insight を開く気になるか。
6. **回帰がないか**: WinSxS 展開・recycle・handoff notice・reclaimable が従来通り動く。

→ 1〜5 が満たされたら v0.5.9 は成功。特に **5** が最終ゲート。
