# v0.5.15 大容量ノード視覚表現 設計メモ

## ステータス

v0.5.15-A/B の実装（行背景色による強調）は **採用せず revert 済み**。  
次回実装前に適用範囲と表現方法をユーザー確認してから着手する。

---

## 背景・動機

### dogfooding FB

- ドライブ内でディスクを消費しているフォルダ/ファイルが分かりにくい
- `%` 表示だけでは「どの程度大きいか」が直感的に伝わりにくい
- 現在のシンプルな Tree-first UI 自体は悪くない
- 一定以上を占めるノードをフォント/背景/アクセントなどで分けたい
- 閾値は変更可能にしたい

### v0.5.15-A/B で試みたこと

- TreeView rows に `tree-row--large` class を追加
- 閾値以上の行に amber 半透明背景 + 左 border アクセント + 名前太字を適用
- Highlight selector (Off / ≥1% / ≥3% / ≥5% / ≥10%) を TreeView ヘッダーに追加
- localStorage で設定を永続化

### 採用しなかった理由

- 「全然イメージと違う」
- 行背景色の強調は、選択行・hover・focus との競合が起きやすく視覚的に違和感
- TreeView だけが変わり、Largest / Top リストが変わらないため画面全体として一貫しない
- まず「どこに適用するか」「どう表現するか」を整理してから実装すべき

---

## 論点 A: 何を強調したいのか

| 目的 | 補足 |
|------|------|
| 割合が大きいノードを即座に見つけたい | `%` 表示は既にあるが、行をスキャンする必要がある |
| 絶対サイズとして大きいことも伝えたい | 5% でも 100GB ドライブなら 5GB — 絶対値も重要 |
| 削除候補を探す補助表現にしたい | 常時警告ではなく「大物を探す」ためのガイド |
| シンプルな Tree-first UI は壊したくない | 過剰な装飾、色の氾濫は避ける |

---

## 論点 B: 適用範囲

### 今回の反省

TreeView だけ強調しても、Largest / Top のリスト側が変わらないため画面全体として一貫しない。

### 次回検討対象と優先度

| 対象 | 検討 | 理由 |
|------|------|------|
| TreeView rows | 要確認 | ユーザーが最もよく使う画面だが、行背景は違和感あり |
| Largest Directories | ◎ 有力 | 既に size / % 列がある。ここだけでも十分かもしれない |
| Largest Files | ◎ 有力 | 同上 |
| Top Directories (scan top_directories) | ◎ 有力 | 同上 |
| Top Files (scan top_files) | ◎ 有力 | 同上 |
| Search inside folder results | △ 後回し | 使用頻度が低い |
| Bookmarks panel の size/% | △ 後回し | 既に size/% を表示済み。追加強調は複雑化 |
| SelectedFolderCard / Insights header | ✕ 対象外 | ここは個別フォルダの詳細 |

**推奨**: まず Largest / Top リスト → TreeView の順で検討する。

## 論点 C: 表現候補

### 候補 1: 行背景色 ← 今回試して不採用

- **欠点**: 選択行 (blue) / hover / focus と競合しやすい
- **欠点**: 行全体が着色されると、大量行が強調されたとき逆に読みにくい
- **欠点**: シンプルな UI の印象が崩れる

### 候補 2: size / % の文字強調 ← 有力

- size / % の数字だけを太くする、または色を少し変える（例: `font-weight: 650`, `color: #b45309`）
- TreeView / Largest / Top で共通化しやすい
- 行全体の見た目を壊さない
- **欠点**: size 列を見ないと気づかない可能性

### 候補 3: 小さな badge

- "5%+" / "10GB+" のような小バッジを size 列の横や行末に付ける
- 分かりやすいが UI がうるさくなりやすい
- **欠点**: バッジが増えると視線が散る

### 候補 4: size bar の表現強化 ← 有力

- 現在の size bar（薄い blue の背景グラデーション）を、閾値以上で少し濃くする / 色を変える
- TreeView の size bar（`tree-size-bar`）と Largest/Top テーブルで共通化できる
- 「容量感」を視覚的に出しやすく、行背景より自然
- **欠点**: size bar を持たないパネルへの統一が必要

### 候補 5: アイコン / 左アクセント

- 行背景より控えめ
- **欠点**: 意味が伝わりにくい可能性
- v0.5.15-A/B でも左 amber アクセントは入れたが、背景色と組み合わせると重くなった

### 候補 6: Insights / リスト側のみ強調、TreeView はシンプル維持

- TreeView はシンプル維持（現状維持）
- Largest / Top / Search results でのみ強調する
- Tree-first の直感性には弱いが、UI の一貫性は保ちやすい

## 論点 D: 閾値の考え方

### % threshold

| 値 | 意味 |
|----|------|
| 1% | 1TB ドライブなら 10GB 以上 |
| 3% | 1TB ドライブなら 30GB 以上 |
| 5% | 1TB ドライブなら 50GB 以上（初期値候補） |
| 10% | 1TB ドライブなら 100GB 以上 |

### 絶対サイズ threshold

| 値 | 意味 |
|----|------|
| 1 GB | 小さいドライブでも意味がある |
| 5 GB | 一般的な「大きいファイル」感覚 |
| 10 GB | 明らかに大きい |

### OR 条件の検討

`>= N% OR >= M GB` の複合条件にする案:

- 例: `>= 5% OR >= 10GB`
- 小容量ドライブで % が低くても、絶対値が大きい場合をカバーできる
- UI が複雑になるため、初期実装では % のみでもよい

### Off の有無

- Off を必ず用意する（デフォルト表示を変えたくないユーザー向け）

### localStorage 永続化

- ユーザーが変更した閾値は次回起動時も維持する（v0.5.15-A/B でも実装済みで問題なし）

## 論点 E: 推奨案

### 案 A（推奨: まず Largest / Top リストで試す）

**範囲**: Largest Directories / Largest Files / Top Directories / Top Files  
**表現**: size 列の数字の色 / font-weight を閾値以上で変える  
**TreeView**: この段階では変更しない  
**閾値**: `>=5%`（Off も用意）

メリット: リストは既に size 列があり変更が局所的。画面全体の印象を壊しにくい。  
デメリット: TreeView を見ているときに大物が目立たない。

---

### 案 B（TreeView + Lists で size/% と size bar を統一強調）

**範囲**: TreeView + Largest / Top  
**表現**:
- size/% の数字に `color: #b45309` (amber-600 / warm brown) などを適用
- size bar を閾値以上で少し濃く（例: `rgba(245, 158, 11, 0.25)` → `rgba(245, 158, 11, 0.45)`）
- 行背景は変えない

**閾値**: `>=5%`（Off も用意）

メリット: TreeView にも反映されるが行背景を使わない。size/% を見る動線に乗る。  
デメリット: TreeView と Largest/Top で size bar の CSS クラスが別実装のため、統一に工数がかかる。

---

### 案 C（絶対サイズ + % の OR 条件で Largest / Top のみ）

**範囲**: Largest Directories / Largest Files のみ  
**表現**: badge または size 列テキスト強調  
**閾値**: `>= 5GB OR >= 5%`  
**TreeView**: 変更しない

メリット: 「大物を探す」ユースケースには十分。実装が最も小さい。  
デメリット: TreeView での視認性向上なし。

---

## 実装前に確認すべき事項

ユーザーに確認:

1. **TreeView にも強調が必要か**（Largest / Top だけでよいか）
2. **行背景色は避けるか**（候補 2/4 ≫ 候補 1）
3. **% のみ、または絶対サイズ条件も必要か**
4. **閾値 UI はどこに置くか**（TreeView ヘッダー / 全体設定 / リストごと）
5. **Largest / Top / TreeView を同じ表現で統一するか**

---

## 今回の結論

- v0.5.15-A/B の行背景強調は採用しない
- 次回は「行全体の背景」ではなく、**size / percent / size bar のような「容量を表す部分」に寄せる**方が有力
- 適用範囲は **TreeView だけでなく、Largest / Top / Search results も含めて一貫性を検討する**
- **実装前にユーザー確認を挟む**
