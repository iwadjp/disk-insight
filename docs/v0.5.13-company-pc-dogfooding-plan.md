# v0.5.13-A: Company PC Dogfooding Plan

会社PC（厳格なセキュリティ環境）で disk-insight を **正当に・説明可能な形で** dogfooding するための
security / packaging / distribution 方針を整理する。

- **本ドキュメントは設計・リスク整理・実行計画のみ。** コード変更・署名・配布・GitHub Release は含まない。
- **方針の大原則:** セキュリティ製品（Defender / EDR / SmartScreen）の無効化・回避・検知回避は一切提案しない。
  社内ルールに従い、許可される範囲でのみ実行する。「引っかかったら使わない」を既定とする。
- 対象バージョン: v0.5.12-H 完了時点の挙動を棚卸しした上で記述。

## 0. 前提となる現状挙動（実コードで確認済み）

> このセクションは推測ではなく、`src-tauri/src/main.rs` / `tauri.conf.json` / `src/mft_probe.rs` を直接確認した結果。

| 項目 | 事実 | 確認元 |
|------|------|--------|
| ネットワーク通信 | **なし。** HTTP/socket クライアントコードは存在しない。`devUrl: http://127.0.0.1:1420` は dev サーバ（Vite）専用で release には含まれない | `tauri.conf.json`、Cargo 依存に reqwest/hyper 等なし |

| 外部プロセス起動 | `explorer.exe`（開く / select）、`ShellExecuteExW "properties"`（プロパティ）、`powershell.exe`（Open terminal here）、`ShellExecuteExW "runas"`（admin 再起動） | `main.rs:907,922,937,1026,1295` |
| ファイル削除 | **Recycle Bin への移動のみ**（`move_to_recycle_bin`）。完全削除 API は使わない。Advanced Mode 限定 | `main.rs` invoke_handler |
| 低レベルディスクアクセス | NTFS MFT を raw volume handle（`\\.\C:`）で読み取り。**読み取り専用** | `src/mft_probe.rs` |

**結論（棚卸し）:** disk-insight は「外部通信なし・自動更新なし・削除は Recycle のみ・書き込みは自前の LOCALAPPDATA のみ」という、
セキュリティ的には **説明しやすい** 部類のツール。会社PCで問題になりうるのは挙動そのものより **未署名であること** と **admin / 低レベル read / PowerShell 起動** の見え方。

## 1. 会社PC dogfooding の前提整理

### 実行前に確認すべきこと（自分では決められない＝社内ルール依存）

- [ ] 個人作成（社外作成）ツールを会社PCで実行してよいか（持ち込みソフトの可否）
- [ ] 管理者権限での起動が許可されるか（そもそも一般ユーザーが UAC 昇格できるか）
- [ ] ローカルディスク容量分析ツールの利用が許可されるか
- [ ] 社外クラウド通信が「ない」ことを説明資料で示せば足りるか
- [ ] ログ / telemetry / network がないことの説明で足りるか
- [ ] NTFS / MFT の raw 読み取りが社内 DLP / EDR ポリシー上問題ないか（情報持ち出し検知に触れないか）

### 結論

- **社内ルール違反にならない範囲でのみ dogfooding する。** 不明な点は IT/情報システム部門に確認してから。
- **セキュリティソフトを無効化・例外登録を強要する方針は取らない。** 例外登録が必要なら、それを判断するのは IT 側。
- 上記が「不可」または「不明」のままなら、**会社PCでは dogfooding しない**（自宅PCに留める）。

## 2. セキュリティ製品に引っかかりそうな要因（リスク表）

リスク度: 🔴高 / 🟡中 / 🟢低

| 要因 | リスク | 会社PC dogfooding への影響 | mitigation（回避ではなく正当な低減策） |
|------|:----:|------|------|
| 未署名 exe（unknown publisher） | 🔴 | SmartScreen / AppLocker / WDAC で実行ブロックされうる最大要因 | コード署名（§5）。または IT による明示的許可。署名なしで無理に実行しない |
| SmartScreen reputation（実績ゼロ） | 🔴 | 署名しても初期は評価ゼロで警告が出る | 署名 + 時間経過で改善。dogfooding 段階では「警告が出る＝正常」と理解し、IT 許可下でのみ続行 |
| 管理者権限要求 | 🟡 | 一般ユーザーが昇格不可な環境では scan 不能 | 非 admin の read-only degraded mode（§6）。admin 必須を UI で明示 |
| `ShellExecuteEx "runas"`（admin 再起動） | 🟡 | UAC 昇格を伴う自己再起動は EDR が「昇格を試みるプロセス」として記録しうる | company-safe mode で非表示化（§7）。挙動を説明資料に明記 |
| `powershell.exe` 起動（Open terminal here） | 🔴 | **EDR が最も嫌う挙動。** 子プロセスに powershell を spawn するのはマルウェア類似挙動として高確度で検知 | **company-safe mode で完全に無効化（§7）。会社PCでは封印する最優先項目** |
| `explorer.exe` 起動（開く / select） | 🟢 | explorer 起動は一般的で低リスク | 通常は許容。気になるなら safe mode で抑制可 |
| `ShellExecuteEx "properties"`（プロパティ） | 🟢 | shell verb 呼び出しは低リスク | 通常は許容 |
| NTFS / MFT 低レベル read（`\\.\C:`） | 🟡 | raw volume handle は一部 EDR が「ディスク直接アクセス」として監視。DLP が情報収集と誤認する可能性 | 読み取り専用であることを説明。書き出し先が画面と LOCALAPPDATA のみであることを明示 |
| Recycle Bin 操作 | 🟢 | Recycle への移動は標準 shell API、低リスク | Advanced Mode 限定を維持。safe mode で無効化可 |
| 自動 updater | 🟢 | **現状なし。** 将来入れると外部通信＋自己書き換えで一気に高リスク化 | **dogfooding 用ビルドには updater を入れない**ことを明文化 |
| 外部通信 | 🟢 | **現状なし** | 「通信なし」を説明資料の中心に据える |
| portable exe / zip 展開実行 | 🟡 | Mark-of-the-Web 付き zip からの実行は SmartScreen 警告。AppLocker が未署名 exe をブロック | 署名 + 配置場所を IT 許可ディレクトリに。zip は社内手段で受け渡し |

## 3. パッケージング方針

### 候補比較

| 方式 | 会社PCでの安全性 / 説明しやすさ | 判定 |
|------|------|:----:|
| 署名済み installer (msi/nsis) | 最も説明しやすい。配置・アンインストールが追跡可能 | ◎（Release 時の最終形） |
| 署名済み単体 exe | 署名があれば SmartScreen 緩和。portable で取り回しやすい | ○（dogfooding 現実解） |
| 未署名 portable zip | unknown publisher + MotW で止まりやすい | △（IT 許可がある場合のみ） |
| 未署名単体 exe | 同上。最も止まりやすい | △ |
| GitHub Release asset | 今回は **行わない** | ✕（対象外） |

### 方針

- **dogfooding の現実解は「署名済み単体 exe（portable）」。** installer は Release 時に検討。
- **署名がない状態で会社PCに持ち込まない。** 未署名 zip での持ち込みは避ける。
- portable の方が「インストールしない＝環境を汚さない」点で dogfooding 段階では説明しやすいが、
  **未署名 portable は AppLocker/WDAC で止まりやすい**ため、署名が前提。
- どの方式でも **updater を含めない**。

## 4. コード署名の必要性

| 論点 | 判断 |
|------|------|
| Authenticode signing の有無 | 会社PC dogfooding には **実質必須**（SmartScreen / AppLocker 対策） |
| 個人開発で証明書を取得すべきか | dogfooding を会社PCで本気でやるなら OV/標準コード署名証明書の取得を検討。EV だと SmartScreen 即時評価が付くが高価 |
| GitHub Release 前に署名すべきか | **Release するなら署名は前提**にしたい（未署名公開はユーザー全員に警告が出る） |
| 自宅 / 会社で方針を分けるか | **分ける。** 自宅PCは未署名で dogfooding 可。会社PCは署名 or 社内許可が前提 |
| 署名なしで会社に持ち込むリスク | 実行ブロック / 警告 / EDR フラグ / IT 監査での指摘。**無理に実行しない** |

**結論:** 会社PC dogfooding には **署名または社内の明示的許可が望ましい**。どちらも無い状態では会社PCで実行しない。

## 5. 管理者権限の扱い

- 現状: v0.5.12-B で admin 警告バナー + "Relaunch as administrator"（`runas`）を実装済み。
- 会社PCでの懸念:
  - 一般ユーザーが UAC 昇格できない環境では admin 再起動が機能しない。
  - 自己 `runas` 再起動は EDR に「昇格を試みるプロセス」として記録される可能性。
- 方針:
  - **非 admin でも動く read-only degraded mode に価値がある。** scan 不能でも、cache 済みデータの閲覧・bookmark 確認は admin 不要でできるようにする余地（§7 / v0.5.13-B 候補）。
  - 会社PCでは **admin 再起動ボタンを非表示 or 警告のみ**にできる company-safe mode が望ましい。
  - admin が必要な理由（MFT raw read）を UI と説明資料の双方に明記する。

## 6. Company-safe mode の必要性

会社PC dogfooding 用に、EDR/DLP に触れやすい挙動を封じる mode を **設ける価値が高い**。

| 封じる候補 | 会社-safe mode での扱い | 優先度 |
|------|------|:----:|
| Open terminal here（powershell 起動） | **完全無効化（非表示）** | 🔴最優先 |
| relaunch as admin（runas） | 非表示 or 警告のみ | 🟡 |
| Advanced Mode（削除系の入口） | 非表示 | 🟡 |
| Move to Recycle Bin | 無効化 | 🟡 |
| 外部プロセス起動（explorer / properties） | 抑制 or 維持（低リスクなので維持寄り） | 🟢 |
| network なしの明示 | UI に「No network access」表示 | 🟢 |
| read-only scan/viewer mode | scan + 閲覧のみに限定 | 🟡 |

### 既存 Safe Mode との関係

- 既存の **Safe Mode / Advanced Mode** は「削除など破壊的操作の解禁トグル」であり、**安全仕様は変更しない**。
- **company-safe mode は別軸**：「会社PC向けに powershell 起動・admin 再起動など外部から疑われる挙動を封じる起動モード」。
  破壊的操作の安全境界（`validate_recycle_target` 等）には手を入れない。
- 実装するなら、起動時フラグ / 環境変数 / ビルド feature のいずれか（v0.5.13-B で設計）。最も説明しやすいのは **ビルド時に company 版を分ける**か **起動時環境変数**。

## 7. セキュリティ説明用ドキュメント（テンプレート）

会社IT に説明を求められた場合に提示できるよう、**説明テンプレートを docs に常備する価値が高い**。
以下を `docs/security-overview.md`（v0.5.13-B 候補）として整備する想定の雛形:

```
disk-insight — Security Overview (for IT review)

What it does:
  Reads the NTFS Master File Table (MFT) of a local drive to visualize
  per-file / per-folder disk usage (WizTree-like). Read-only analysis tool.

Disk access:
  Local volumes only. Opens a raw volume handle (\\.\C:) to read the MFT.
  READ-ONLY. It never writes to the raw volume.

Network:
  NONE. No HTTP client, no telemetry, no auto-update, no external endpoints.
  (Verifiable: no reqwest/hyper/updater dependency; no socket code.)

Write operations:
  - Reads disk; does not modify scanned files.
  - Optional "Move to Recycle Bin" only (Advanced Mode), via standard
    Windows shell API. No permanent deletion.

Local files written:
  %LOCALAPPDATA%\disk-insight\bookmarks.json  (user bookmarks)
  %LOCALAPPDATA%\disk-insight\cache\          (scan cache)
  Nothing outside the user's LOCALAPPDATA.

Child processes (only on explicit user action):
  - explorer.exe          (open / reveal a folder)
  - "properties" shell verb (file properties dialog)
  - powershell.exe        (Open terminal here)  ← disabled in company-safe mode
  - self relaunch via "runas" (request admin)   ← optional

Administrator privileges:
  Required to read the MFT (raw volume access). Without admin, scanning is
  limited; cached data can still be viewed.

Code signing:
  [signed with <cert> / currently unsigned — pending].
```

## 9. 結論

### 会社PC dogfooding 前に「必須の確認」（社内ルール）
- 個人作成ツールの実行可否 / 管理者昇格の可否 / raw disk read が DLP・EDR ポリシーに触れないか。
- ひとつでも不可・不明なら **会社PCでは実行しない**。

### 会社PC dogfooding 前に「実装すべきこと」
- **company-safe mode（v0.5.13-B）**: 最優先で powershell 起動（Open terminal here）を封じる。admin 再起動・Advanced・Recycle も封じられるように。
- `docs/security-overview.md`（説明テンプレートの実体化）。

### 実装しなくてもよいこと
- ネットワーク無効化機構（そもそも通信がない）。
- updater の削除（そもそも無い。「入れない」方針の明文化で足りる）。
- 既存 Safe / Advanced の安全仕様変更（触らない）。

### GitHub Release 前に必要なこと
- コード署名（未署名公開は全ユーザーに警告）。Release は今回スコープ外。

### 署名は必要か
- **会社PC dogfooding には必要（または社内の明示許可）。** 自宅 dogfooding には不要。

### company-safe mode は必要か
- **必要。** 特に powershell 起動の封印は会社PCでの最大の地雷回避。
