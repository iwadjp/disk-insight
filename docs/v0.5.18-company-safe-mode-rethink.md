# v0.5.18 Company-safe Mode Rethink

## Status

- **Docs only.** v0.5.18-B does not change any code.
- No UI removal, no script changes, no package rebuild.
- This document records the reasoning and recommended direction before implementation.

---

## 1. Problem Statement

Company-safe mode was introduced to suppress risky-looking operations when
running disk-insight on a company PC. The original motivation was sound: hide
terminal launch, admin relaunch, Advanced Mode, and Move to Recycle Bin from a
dogfooding build so that security reviewers or IT would not flag them.

However, the Normal Mode safety model has matured since then, and the checkbox
now causes more problems than it solves:

- **Inverse anxiety.** A "Company-safe" toggle implies that the Normal (non-safe)
  state carries additional risk. Users reasonably ask: *Is Normal Mode unsafe? Did
  I forget to enable Company-safe?* The checkbox makes Normal Mode look weaker
  than it actually is.
- **Three-layer safety model.** Normal / Company-safe / Advanced is hard to
  explain. Reviewers and dogfooders need to understand what each layer suppresses,
  where the boundaries are, and which combinations are valid.
- **Duplicate suppression.** Most of what Company-safe hides is already absent or
  gated in Normal Mode. Move to Recycle Bin requires Advanced Mode — which is off
  by default and session-only — whether or not Company-safe is enabled.
- **Maintenance burden.** Every new feature or context menu item needs a
  `companySafeMode` branch. Missing a branch is a silent bug.
- **Company PC explanation can be docs-only.** A README and SECURITY-OVERVIEW
  document the safety posture more durably than a UI toggle that could be left in
  the wrong state.

## 2. Current Safety Model

### Normal Mode (default)

| Property | State |
|----------|-------|
| Network connections | None |
| Auto-updater | None |
| Telemetry | None |
| Console window (release build) | Hidden (`windows_subsystem = "windows"`) |
| TreeView / scan / visualization | Available |
| Explorer handoff (Show in Explorer, Select file) | Available |
| Copy path / Copy quoted path | Available |
| Bookmarks | Available |
| Review list / batch copy paths | Available |
| Destructive file operations | Not implemented (Delete / Rename / Cut / Paste) |
| Move to Recycle Bin | Hidden unless Advanced Mode is explicitly ON |
| Terminal launch | Available (PowerShell here) |
| Admin relaunch | Available |
| Advanced Mode | Available but off by default |

### Advanced Mode

| Property | State |
|----------|-------|
| Activation | Explicit opt-in, acknowledgement required |
| Persistence | Session-only; resets to off on next launch |
| Move to Recycle Bin | Shown (with per-item confirmation modal) |
| Confirmation | Modal with path + size + risk warnings |
| Company-safe interaction | Currently suppressed by Company-safe ON |

### Company-safe Mode (current)

| Property | State |
|----------|-------|
| Activation | Toolbar checkbox |
| Persistence | Session-only |
| Terminal launch | Hidden |
| Admin relaunch | Hidden |
| Advanced Mode | Disabled (checkbox hidden / suppressed) |
| Move to Recycle Bin | Hidden (Advanced Mode is disabled) |
| Overlap with Normal Mode | Large — most suppressed items are already gated |

## 3. Options Considered

### Option A: Remove Company-safe checkbox

Remove the Company-safe UI entirely. Simplify to Normal + Advanced two-layer
model. Company PC explanation moves to README / SECURITY-OVERVIEW / BUILD-INFO.

**Pros:**
- Simpler UI; one fewer mode to explain.
- Normal Mode stands alone as the safe default — no inverse anxiety.
- "Did I forget to enable Company-safe?" problem disappears.
- Every new feature only needs one safety code path.
- Company PC documentation becomes the source of truth, not a runtime toggle.

**Cons:**
- No explicitly labeled "Company-safe" in the UI.
- If a future audit requires Advanced Mode itself to be unavailable, a separate
  design is needed (see Option B).

### Option B: Move Company-safe to build / package policy

Remove the UI checkbox. If a restricted package is needed, gate Advanced Mode /
terminal / recycle / admin relaunch via a build-time flag or runtime config
embedded in the package — not a UI toggle.

**Pros:**
- UI stays simple.
- The restricted package is a distinct artifact with a clear policy statement.
- "This package has Advanced Mode disabled" is a package property, not a user
  setting.

**Cons:**
- Adds a build variant to maintain and test.
- Not needed unless an audit specifically requires it.
- Premature until dogfooding shows the need.

### Option C: Rename to Read-only mode / Safe viewing mode

Replace "Company-safe" with a general-purpose safe-viewing label.

**Pros:**
- Not company-specific.

**Cons:**
- Normal Mode is already effectively read-only. The rename creates confusion:
  *Is Normal Mode not read-only?*
- Does not reduce the three-layer complexity.
- The underlying maintenance burden remains.

### Option D: Keep but move to settings / hide from toolbar

Keep the feature but remove it from the toolbar; surface it in a settings panel
or safety info section.

**Pros:**
- Feature is preserved.

**Cons:**
- Half-measure. The maintenance burden and code branches remain.
- A hidden toggle is not obviously useful.
- Safety model is still three-layer in code even if visually simpler.

---

## 4. Recommended Decision

```
Adopt Option A now.
Keep Option B as a future fallback if a restricted build is explicitly required.
Drop Option C and Option D.
```

Rationale:

- Normal Mode's safety posture is already strong enough for dogfooding on a
  company PC.
- Company PC explanation is better served by documentation than by a UI toggle.
- Option A reduces code complexity and removes the inverse-anxiety problem.
- Option B is available if a future audit requires Advanced Mode to be
  unavailable at the package level — but should not be built speculatively.

## 5. New Safety Model (after Option A)

```
Normal Mode
-----------
Default. The standard safe state.

- Visualization / scan / TreeView
- Explorer handoff (Show in Explorer, Select file)
- Copy path / Copy quoted path
- Properties
- Bookmarks
- Review list / batch copy paths
- No destructive file operation (no Delete / Rename / Cut / Paste)
- Move to Recycle Bin: NOT shown
- No network communication
- No auto-updater
- No telemetry

Advanced Mode
-------------
Explicit opt-in for a single session.

- Activation: manual toggle, acknowledgement required
- Persistence: session-only (resets on launch)
- Unlocks: Move to Recycle Bin
- Each risky action: per-item confirmation modal
- Risky paths: path-based warning check before confirming
```

Key framing principles:

- Normal Mode is the standard safety state, not a "less safe" alternative.
- Advanced Mode is the explicit opt-in gate for risky operations — its existence
  does not make Normal Mode unsafe.
- Company PC explanation lives in documentation, not in a UI toggle.

## 6. Company PC Explanation After Removal

After Company-safe checkbox removal, the README and SECURITY-OVERVIEW carry the
explanation.

**Candidate wording for README-company-safe.txt / README-dogfooding.txt:**

```
In the default state, disk-insight does not perform destructive file operations.
Move to Recycle Bin is not shown unless the user explicitly enables Advanced Mode
for the current session.
The app has no network communication, no auto-updater, and no telemetry.
```

**Japanese memo:**

```
通常状態では、削除・移動・名前変更などの破壊的操作は表示されません。
ごみ箱への移動は、ユーザーがセッション中に Advanced Mode を明示的に有効化した
場合のみ表示されます。
ネットワーク通信、自動更新、テレメトリはありません。
```

Sections to update:

- `docs/security-overview.md` — rewrite safety model section for Normal / Advanced
- `README-company-safe.txt` (or rename to `README-dogfooding.txt` / `README-security.txt`)
- `BUILD-INFO.txt` — remove `Company-safe mode: implemented` line; replace with
  plain safety summary

## 7. Implementation Plan After This Docs Phase

### v0.5.18-C: Remove Company-safe UI

Changes to `ui/src/main.tsx`:

- Remove `companySafeMode` state and all setter calls
- Remove Company-safe toolbar checkbox and its label / tooltip
- Remove Company-safe banner / modal (if any)
- Remove all `companySafeMode` props from `SafeContextMenu`, `BookmarksBar`,
  `ReviewListPanel`, and any other component that receives it
- Remove Company-safe-conditional suppression of terminal, admin relaunch, recycle,
  and Advanced Mode
- Verify that Advanced Mode remains functional as the standalone risky-op gate
- Verify that terminal / admin relaunch remain available in Normal Mode (their
  existing conditions apply — no new gating needed)
- Review list / Bookmarks / Copy paths: no change expected

Changes to `ui/src/styles.css`:

- Remove any `.company-safe-*` CSS classes

### v0.5.18-D: Update Company-safe Docs and Package Wording

- `docs/security-overview.md` — update to Normal / Advanced two-layer model
- `docs/company-safe-build.md` — keep as historical reference, or rewrite as
  general dogfooding build notes
- `docs/company-pc-dogfooding-checklist.md` — remove Company-safe ON instruction;
  replace with Normal Mode safety summary
- `scripts/build-company-safe.ps1` — keep or rename to `build-dogfooding.ps1`;
  remove Company-safe mode check; keep SHA256, debug flag checks, and security
  notes
- `README-company-safe.txt` generation in script — remove Company-safe ON
  instruction; expand Normal Mode safety description
- `BUILD-INFO.txt` generation — remove `Company-safe mode: implemented` line;
  add ASCII-safe separators (avoid em dash to prevent Shift-JIS mojibake)

### Future: Restricted Build Policy (Option B)

Pursue only if a specific audit requirement mandates that Advanced Mode must be
unavailable at the package level.

- company-restricted build variant
- Advanced Mode disabled by build flag or embedded config
- terminal / recycle / admin gated by package policy
- not a UI checkbox — a package property
- requires separate build pipeline and verification
