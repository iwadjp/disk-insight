TreeView cleanup visibility — 比較モック

disk-insight v0.5.16-D  ·  実装前ユーザー確認用  ·  サンプル: 容量降順の混在ノード（深さは比較のため平坦表示） ·  本体コード変更なし

方針: これは「容量 × cleanup safety 分類」を TreeView 上でどう見せるかの比較モックです。 分類は cleanupSafety.ts のパスヒューリスティックに基づく参考情報で、 disk-insight は削除を推奨しません。「safe to delete」「delete recommended」などの表現は使いません。 容量バー（どれだけ大きいか）と safety marker（手動で触ると危ないか／確認候補か）は役割を分けています。
Safety tone 凡例（cleanupSafety.ts と対応）
Protected system — 手動操作は避ける（strong-caution）
App-managed — アプリ経由を推奨（caution）
Review candidate — 確認候補 cache/temp/deps/bin（review）
User data — 内容を理解している時のみ（neutral）
Unknown — 指針なし（none / 表示控えめ）
A: 現状維持 B: safety marker 列 C: name 後 pill D: bar tone accent E: filter / view mode F: Insights list 比較表 / 推奨

第一候補 案 E — filter / view mode（常時表示は変えない）
TreeView header に view 切替を置く。通常は All（＝案 A の現状）で何も足さない。 Large review candidates を選ぶと、確認候補（cache / temp / deps / bin）だけに絞り込む。 常時表示のシンプルさを保ったまま「素早く見つける」を満たす。下は絞り込み適用後の状態。

比較表 / 推奨 比較表と実装候補

評価軸: 大きい cleanup 対象を素早く見つけられるか / TreeView がごちゃつかないか / 削除推奨に見えないか / 容量バーと競合しないか / 実装・誤誘導リスク。詳細比較は docs/v0.5.16-tree-cleanup-visibility-options.md の表を参照。

第一候補: 案 E — filter / view mode
“Large review candidates” に絞り込めて目的に直結。通常は All で現状のシンプルさを完全維持。 「削除してよい」ではなく「確認候補」というフレーミングにできる。 弱点は view 切替への気づきにくさと、lazy 展開との整合設計。
第二候補: 案 B — safety marker 列
TreeView 完結に近く、容量バーと役割を分離できる。 弱点はマーカー記号のノイズと直感性。色ドット案との比較が必要。

見送り寄り: 案 D は容量バーの意味が「容量／安全性」で混ざり誤誘導リスクが最大。 案 C は name 列圧迫が大きい。 案 F は目的に合うが TreeView 完結から離れるため優先度低（E の補助なら可）。

本フェーズ (v0.5.16-D) は本実装しない。次フェーズでユーザーが第一/第二候補を選んでから実装に進む。
