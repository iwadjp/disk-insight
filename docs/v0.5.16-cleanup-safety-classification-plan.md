# v0.5.16 Cleanup Safety Classification — 設計メモ

## ステータス

**v0.5.16-A はコード変更なし。設計ドキュメントのみ。**

dogfooding で残っている課題:

> 手作業で削除してよい箇所と、そうではない箇所をより区別したい

TreeView は「容量を消費している場所」を見つける方向で改善中（v0.5.15 系の occupancy bar）。
本メモは、その次の段階「見つけた後に**触ってよいかを見分ける**補助表示」をどう設計するかを整理する。

**重要前提:** disk-insight は「削除して安全」とは断言しない。分類はあくまで判断補助であり、最終判断はユーザーが行う。

---

## 1. Problem statement

容量の大きい場所を見つけても、ユーザーは次に「ここを触ってよいか」を判断する必要がある。

ユーザーが知りたいこと:

- ここは手作業で削除してよい場所なのか
- ここは Windows / アプリ / 開発環境に必要で危ない場所なのか
- ここはキャッシュ／一時ファイルなので確認対象にしてよいのか
- ここはユーザーデータなので、削除は自己判断が必要なのか

disk-insight はこの判断を補助したい。しかし:

- 「Safe to delete」のように削除を推奨する UI は危険。
- パスパターンだけでは確実な判定はできない（誤判定リスク）。
- アプリ／開発環境の構成は人によって違う。

→ **「分類して説明する」までに留め、「削除を勧める」UI は作らない。**

## 2. Classification categories（分類案）

| Category (内部 key) | 表示ラベル (EN) | 表示ラベル (JA) | 意味 | 代表例 | UI tone |
|---|---|---|---|---|---|
| `protected-system` | Protected system | システム保護領域 | 手動削除を避けるべき OS 領域 | `C:\Windows`, `WinSxS`, `System Volume Information` | 強い caution |
| `app-managed` | App-managed | アプリ管理領域 | アプリの設定／アンインストーラ経由が望ましい | `Program Files`, `Program Files (x86)`, `ProgramData` | caution |
| `user-data` | User data | ユーザーデータ | ユーザー自身のデータ。削除は自己判断 | `Documents`, `Pictures`, `Desktop`, `VirtualBox VMs` | neutral |
| `cache-candidate` | Cache candidate | キャッシュ候補 | キャッシュらしい名前。関連アプリ終了後に確認 | `Cache`, `.cache`, browser cache | review candidate |
| `temp-candidate` | Temp candidate | 一時ファイル候補 | 一時ファイルらしい名前 | `Temp`, `tmp`, `AppData\Local\Temp` | review candidate |
| `dev-dependency` | Dev dependency | 開発依存物 | 再生成可能なことが多いがプロジェクト依存 | `node_modules`, `target`, build folders | review candidate |
| `recycle-bin` | Recycle bin | ごみ箱 | ごみ箱領域 | `$Recycle.Bin` | review candidate |
| `unknown` | Unknown | 不明 | 判定不能 | その他すべて | no badge |

### tone の意味

| tone | 意味 | UI 上の扱い |
|---|---|---|
| 強い caution | 手動で触るべきでない | 目立つ警告色（amber/red 系）、TreeView badge 候補 |
| caution | 注意。正規手順を推奨 | 控えめ警告色、SelectedFolderCard 中心 |
| neutral | 中立。ユーザー判断 | バッジなし or 弱い neutral |
| review candidate | 確認してよい候補（≠ 削除推奨） | 落ち着いた info 色。**削除を勧める語にしない** |
| no badge | 表示しない | バッジなし |

> **注意:** `review candidate` は「削除してよい」ではなく「**確認の対象にしてよい**」。文言で必ず区別する（§5）。

## 3. Path pattern rules（パターンルール案）

### 3.1 共通方針

- **case-insensitive**（Windows パスは大小無視）。
- **drive letter は任意**（`C:` 固定にしない。`D:\Temp` も temp 候補）。
- **user name は固定しない**（`C:\Users\<any>\...` を正規化して扱う）。
- **localization は今は深追いしない**が、将来課題として記録（§7）。
- **誤判定しやすい pattern は慎重に**（例: 一般名詞 `Cache` は深い階層でのみ採用、ドライブ直下の偶然一致は弱める等）。
- 判定は **path 文字列ベース**。実ファイル内容は読まない（read-only viewer 方針を維持）。

### 3.2 マッチ方式

優先度の高い順に評価し、最初に一致したカテゴリを採用する（**より危険・より具体的なルールを先に**）。

```
1. protected-system   ← 最優先（誤って下位に落とさない）
2. recycle-bin
3. app-managed
4. temp-candidate
5. cache-candidate
6. dev-dependency
7. user-data
8. unknown            ← どれにも当たらなければ
```

### 3.3 ルール表（案）

正規化: パスを小文字化し、`C:\Users\<name>` 部分を `%USERPROFILE%` のように抽象化してから判定する想定。
（実装は v0.5.16-B。ここでは判定意図のみ定義。）

| Category | マッチ条件（意図） | 例 |
|---|---|---|
| `protected-system` | `\Windows` 直下／配下、`\Windows\WinSxS`、`\Windows\Installer`、`\Windows\System32`、`System Volume Information`、ドライブ直下の `$`-prefixed system folder | `C:\Windows\WinSxS` |
| `recycle-bin` | `\$Recycle.Bin`（任意ドライブ） | `C:\$Recycle.Bin` |
| `app-managed` | `\Program Files`、`\Program Files (x86)`、`\ProgramData`（ただし配下の Temp/Cache は下位ルールで上書きしうる→順序注意、後述） | `C:\Program Files\...` |
| `temp-candidate` | path 末尾 or 区切り境界で `\Temp`、`\tmp`、`AppData\Local\Temp` | `C:\Users\x\AppData\Local\Temp` |
| `cache-candidate` | path に `\Cache`、`\.cache`、`\Code Cache`、`\GPUCache`、browser cache 配下 | `...\AppData\Local\Google\Chrome\User Data\Default\Cache` |
| `dev-dependency` | `\node_modules`、`\target`（Rust）、`\.git`、`\build`、`\dist`、`\.gradle`、`\.cargo` | `D:\proj\node_modules` |
| `user-data` | `\Users\<name>\Documents` / `Pictures` / `Videos` / `Music` / `Desktop` / `Downloads`、`VirtualBox VMs`、その他 `Users\<name>` 配下で上記に当たらないもの | `C:\Users\x\Documents` |
| `unknown` | 上記いずれにも当たらない | `D:\misc\foo` |

### 3.4 順序の難所（要検討）

`ProgramData`（app-managed）配下に `Temp` や `Cache` がある場合、どちらを優先するか:

- 案 1: **より深い／具体的な名前を優先**（`...\ProgramData\Foo\Cache` は cache-candidate）。
- 案 2: 親が protected/app-managed なら親を尊重（誤って review candidate にしない）。

→ **v0.5.16-B で「最長一致 + tone 優先度」のどちらを採るか決める。** 安全側に倒すなら案 2 寄り。
本メモでは「迷う場合は安全側（より上位 tone）に倒す」を原則とする。

### 3.5 誤判定が起きやすいパターン（記録）

- ドライブ直下に偶然 `Cache` という名前のユーザーフォルダがある場合。
- `Downloads` を user-data とするか review candidate とするか（**user-data 扱いが安全**。勝手にキャッシュ扱いしない）。
- `Temp` という名前のプロジェクトフォルダ（一時ファイルではない）。
- localization 環境（`ドキュメント` 等のローカライズ表示名）。実フォルダ名は英語のことが多いが要検証。

## 4. UI display proposal（表示案）

### 候補比較

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| A | TreeView name 右に小 badge | 一覧で目に入る | 全行に出すと TreeView がごちゃつく |
| B | 右ペイン SelectedFolderCard に分類＋説明 | 詳細を落ち着いて読める。場所が決まっている | 選択しないと見えない |
| C | hover tooltip / `title` に説明 | 邪魔にならない | 発見性が低い |
| D | Insights に "Cleanup review candidates" 一覧 | 候補をまとめて見られる | 実装重め。誤誘導リスク高 |

### 推奨

**段階導入。** TreeView をごちゃつかせない方針:

1. **SelectedFolderCard（案 B）を主役にする** — 選択中フォルダの分類ラベル＋説明文を表示。情報量を出せる場所はここ。
2. **TreeView は危険領域だけ最小 badge（案 A の限定版）** — `protected-system`（強い caution）のみ小さな caution badge。`review candidate` 系はバッジを出さない（削除を促して見えるのを避ける）。
3. **hover `title`（案 C）は補助** — badge やカードに説明を添える。
4. **Insights の一覧（案 D）は将来検討** — "Cleanup review candidates" は誤誘導リスクが高いので最後。出すとしても「確認候補であり削除推奨ではない」と明記。

> TreeView に全分類バッジを出さない理由: occupancy bar（v0.5.15）で既に情報を足したばかり。さらに全行バッジを足すと一覧性が落ちる。**危険側だけ警告**し、それ以外は選択時に説明する。

## 5. Safety wording（文言案）

### 原則

**NG 表現（使わない）:**

- Safe to delete
- Delete recommended
- Can delete / OK to delete
- Unnecessary / 不要

**採用する方向:** 事実 + 注意喚起。削除是非はユーザー判断であることを明示。

### カテゴリ別 文言（EN / JA）

| Category | EN | JA |
|---|---|---|
| `protected-system` | System-managed area. Avoid manual deletion. | システム管理領域です。手動削除は避けてください。 |
| `app-managed` | App-managed area. Prefer app settings or uninstaller. | アプリ管理領域です。アプリの設定またはアンインストーラの利用を推奨します。 |
| `cache-candidate` | Cache-like name. Review after closing related apps. | キャッシュらしい名前です。関連アプリを閉じてから確認してください。 |
| `temp-candidate` | Temporary-file name. Review after closing related apps. | 一時ファイルらしい名前です。関連アプリを閉じてから確認してください。 |
| `dev-dependency` | Often re-generatable, but project-dependent. Review manually. | 再生成可能なことが多いですが、プロジェクト依存です。手動で確認してください。 |
| `recycle-bin` | Recycle Bin. Empty it from Windows if you intend to free space. | ごみ箱です。容量を空けたい場合は Windows のごみ箱から空にしてください。 |
| `user-data` | User data. Delete only if you recognize it. | ユーザーデータです。内容を理解している場合のみ削除してください。 |
| `unknown` | Unknown. No cleanup guidance available. | 不明です。クリーンアップの指針はありません。 |

### 共通の添え書き（カード末尾）

- EN: *Guidance is heuristic, based on the folder path. disk-insight does not recommend deletion. You decide.*
- JA: *この案内はフォルダパスに基づく推定です。disk-insight は削除を推奨しません。判断はご自身で行ってください。*

## 6. Interaction with existing modes（既存モードとの関係）

参照: `docs/security-overview.md`（§8 安全モデル・§10 Company-safe mode）

| モード | classification の扱い |
|---|---|
| Safe Mode（通常） | **表示のみ。** 分類ラベル＋説明を出す。破壊的操作は増やさない。 |
| Advanced Mode | **表示は Safe Mode と同じ。** 削除系は既存の Advanced Mode safety model（Move to Recycle Bin 限定）に従う。分類は警告補助に使えるが、v0.5.16-A では連携しない。 |
| Company-safe mode | **表示のみ。** 危険操作は一切増やさない。分類バッジ／説明は read-only 情報なので Company-safe でも表示可（ただし「削除を促す表現」は出さないので説明しやすさを損なわない）。 |
| Recycle Bin action | classification は将来「危険領域への Recycle を警告する」補助に使える。**v0.5.16-A では実装しない。** |

**不変条件（全フェーズ通して維持）:**

- Delete / Rename / Cut / Paste は追加しない。
- 「削除して安全」と断言しない。
- ネットワーク／更新／telemetry なし。
- release build で console window を出さない（`#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` を維持）。
- `TREE_FOCUS_DEBUG` / `PERF_LOG` / `PERF_TREE` = false。
